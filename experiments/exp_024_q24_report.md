## Физическая интерпретация

Q24 решает практическую проблему Q23. Переходный метод требовал систему
в фазе роста — редкость для реальных записей, где система обычно в
стационаре. Метод восстановления создаёт переход искусственно: возмущаем
систему и смотрим, как она возвращается.

Это не трюк, а стандартный **стимул-ответный протокол** нейробиологии:
подать стимул, записать восстановление. Физика та же, что в Q23 — хабы
реагируют резко (много входов), листья медленно — но теперь её можно
вызвать по команде, не дожидаясь естественного перехода.

Точность даже выше Q23 (+1.3% vs +9.7% по het), потому что возмущение
контролируемо: все агенты стартуют восстановление с известного уровня,
разброс скоростей чище отражает структуру.

Полный цикл (возмущение → het → водораздел) ошибается на 0.3% — это уже
уровень, на котором можно идти к реальным данным.

## Статус и следующий вопрос

**Q24 ЗАКРЫТ. Фаза 2 завершена.**

**Теперь есть полная цепочка для реальных данных:**
1. Закон `χ·A* = (δ/α_s)·het^(−0.22)` [Фаза 1]
2. het из топологии [Q22]
3. het из стимул-ответной динамики [Q24] ← для реальных записей

**Q25 (Фаза 3) — реальные записи активности:**
Загруженные 2 ГБ записей активности C. elegans. Если там есть
стимул-ответные эпизоды (нейроны возмущаются → восстановление), можно:
- извлечь het из реальной динамики методом Q24
- сверить с het из коннектома (известен точно: 1.58)
- если совпадёт — вся цепочка UAF замкнута на реальных данных

**Нужно понять структуру данных перед Q25:**
- Формат? (кальциевый имейджинг, электрофизиология?)
- Есть ли стимуляция/возмущения?
- Частота дискретизации, длительность, число нейронов?

Это определит, применим ли метод Q24 (нужны восстановления) или Q23
(нужен рост), или потребуется новый метод для чисто стационарных данных.

**Методологический итог Фаз 1–2:** мы прошли путь от «инвариант v5.1
держится только в среднем поле» (Q20) через поправку (Q21), валидацию на
реальном коннектоме (Q22), к извлечению ключевого параметра из одной
динамики (Q23–Q24). Теория теперь операциональна — её можно применить к
системе, о которой известны только временные ряды активности. Это и было
целью v5.2.
